關於

我是吳承祐，宜蘭人。大部分時間在跟交通資料打交道。

從 2025 年開始碰 TDX 的開放資料，本來只是想讓公車動態顯示得好看一點， 後來就一路做成了現在那個監控平台。

寫最多的語言是 JavaScript，需要後端就用 Cloudflare Workers， 要爬資料或寫小工具時用 Python。不太用框架，喜歡能直接打開就看的東西。

座標 宜蘭縣。喜歡火車，也喜歡時刻表這種「承諾式」的設計。

01

我會什麼

不太列進度條

FRONTEND

原生 JavaScript 為主。寫過不少即時更新的看板、地圖介面與資料視覺化。

HTML5 CSS3 / Grid / Flexbox ES6+ Fetch / WebSocket RWD Leaflet

EDGE / BACKEND

後端幾乎都放在 Cloudflare。Workers 負責代理與聚合，D1 存查詢用的資料。

Cloudflare Workers Cloudflare D1 KV / Cache API RESTful API 設計 MJPEG / HLS 代理

DATA / PYTHON

爬蟲、資料清洗、格式轉換。開放資料最大的問題通常是格式會變。

Python 3 Requests / BeautifulSoup pandas TDX / CWA / WRA discord.py

TOOLS

沒有很複雜的工具鏈。能少一個依賴就少一個。

Git / GitHub GitHub Pages Cloudflare Pages VS Code DevTools
02

做過的事

按時間倒序
  • 2026

    網站重做

    把原本的玻璃擬態風格整站換掉，改成紙張質感的編輯排版。順便加了這個部落格。

  • 2025

    CCTV 代理與邊緣快取

    政府網站的串流有跨域、混合內容與連線數三個問題，最後用 Workers 包了一層代理解決。 目前代理約 400 路攝影機。

  • 2024

    監控平台上線

    整合 TDX、高公局、公路局、CWA、WRA 的即時資料。從第一版的單頁地圖， 長到現在 50 多個子頁面、14 個 Workers 微服務。

  • 2023

    開始碰開放資料

    寫了第一個公車動態看板，用 Python 爬資料、存成 JSON、前端每 30 秒抓一次。 後來才發現這是一個很不省電的做法。

03

幾個想法

資訊設計比視覺設計難。 把東西排得好看不難，難的是讓人在兩秒內找到他要的資訊。做看板學到最多的是這件事。

簡潔不是少放東西，是每個東西都有理由。 這句話常被拿來當設計雞湯，但真正要做到，第一步是承認大部分東西都沒有理由。

開放資料的價值在「能組合」。 單一資料源能做的事有限，但把公車、天氣、路況放在一起，就能回答原本回答不了的問題。
